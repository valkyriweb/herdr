---
title: 外部代理
description: 无需终端窗格即可启动、读取、提示、停止和恢复 T3 Code 线程。
---

T3 Code 线程使用常规 `herdr agent` 命令，ID 为 `t3:<thread>`。
前缀后的标识符可能包含冒号。T3 线程没有终端、工作区、标签页或窗格分配。

在 Herdr 配置中指定已批准的 Bifrost 可执行文件绝对路径：

```toml
[server]
t3_adapter = "/absolute/path/to/bifrost"
```

该文件必须支持 `bifrost t3 request`。`HERDR_T3_ADAPTER` 环境变量优先于配置。
适配器继承 Herdr 服务器的环境；请通过现有凭据机制提供 `T3_MCP_ENDPOINT` 和
已批准的 `T3_MCP_TOKEN`。Herdr 不会创建凭据。未配置适配器时 T3 处于禁用状态。
消息投递和监听器监督由 Bifrost 负责。

```sh
herdr agent list
herdr agent start worker --kind t3 --scratch --provider codex --model MODEL
herdr agent start worker --kind t3 --project PROJECT_ID --provider codex --model MODEL --text 'Initial task'
herdr agent status 't3:<thread>'
herdr agent read 't3:<thread>' --after-position 100
herdr agent prompt 't3:<thread>' 'Your prompt' --client-request-id prompt-1
herdr agent stop 't3:<thread>' --client-request-id stop-1
herdr agent resume 't3:<thread>' --client-request-id resume-1
```

启动需要提供者实例、模型，以及现有项目 ID 或 `--scratch`。可选的 `--text`
会提交首条提示。启动没有幂等保证；超时后请先查看线程列表再重试，Herdr 不会自动重试。

提示会排在当前任务之后。停止会中断活动运行并暂停队列，恢复会解除队列暂停。
提示、停止和恢复的结果不确定时，请使用相同请求 ID 和内容重试；新操作使用新 ID。
接受请求不代表任务完成，请通过 `status` 和 `read` 检查。T3 不支持终端等待选项、
focus、attach 或 send-keys。

读取结果包含时间线游标和截断信息。当 `hasMore` 为 true 时，将 `nextPosition`
作为 `--after-position` 继续读取。不支持终端屏幕来源、ANSI 或行数限制。
状态保留 T3 的运行状态、活动运行 ID 和待输入数量。

`agent list` 会协商服务器的 `agent_catalog` 能力。支持时返回后端、能力、标准化
状态和可选的终端位置。T3 列表失败时仍返回终端代理及诊断信息。旧服务器保留原有
仅终端列表格式。支持此能力的服务器会改变 CLI 的 JSON 输出格式；需要原有终端
字段的脚本应直接调用保持不变的 JSON 套接字方法 `agent.list`。

JSON 套接字方法 `agent.external` 接受 `list`、`status`、`read`、`prompt`、
`start`、`stop` 和 `resume`。启动参数为 `title`、`projectId` 或 `scratch`、
`modelSelection: {instanceId, model}` 和可选 `text`。提示、停止和恢复需要
`target` 与 `clientRequestId`；提示还需要 `text`。读取可使用 `afterPosition`。
结果类型为 `external_agent`，`data` 保留适配器回执。旧的 `agent external`
列表、状态、读取和标准输入提示命令仍可使用。

输出上限为 8 MiB，列表超时为 5 秒，其余操作为 2 分钟。现有 JSON 终端方法和
第 1 代端点保持原有格式；不会创建 TUI 窗格或 Herdr Projects 看板条目。
